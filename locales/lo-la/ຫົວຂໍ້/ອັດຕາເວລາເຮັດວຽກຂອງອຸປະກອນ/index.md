# ອັດຕາເວລາເຮັດວຽກຂອງອຸປະກອນ

ອັດຕາເວລາເຮັດວຽກຂອງອຸປະກອນ (device uptime rate) ວັດສັດສ່ວນຂອງເວລາຕິດຕາມທີ່ກຳນົດໄວ້ ທີ່ອຸປະກອນສຸຂະພາບທີ່ເຊື່ອມຕໍ່ — ເຊັນເຊີຕິດຕາມຄົນເຈັບທາງໄກ, ອຸປະກອນສວມໃສ່ ຫຼື ຫົວໜ່ວຍສຸຂະພາບທາງໄກຢູ່ເຮືອນ — ອອນລາຍ, ສົ່ງຂໍ້ມູນ ແລະ ເຮັດວຽກຖືກຕ້ອງແທ້ໆ ແທນທີ່ຈະອອບລາຍ, ຖືກຕັດການເຊື່ອມຕໍ່ ຫຼື ເຮັດວຽກຜິດປົກກະຕິ. ມັນເປັນຕົວຊີ້ວັດໂຄງສ້າງພື້ນຖານທີ່ຢູ່ໃຕ້ທຸກໂຄງການຕິດຕາມທາງໄກ ຫຼື ອຸປະກອນທີ່ເຊື່ອມຕໍ່: ການແຈ້ງເຕືອນທາງຄລີນິກ, ແນວໂນ້ມຕົວຊີ້ວັດຊີວະພາບ ຫຼື ຕົວເລກການມີສ່ວນຮ່ວມທີ່ຄຳນວນຈາກອຸປະກອນທີ່ອອບລາຍເລື້ອຍໆ ເຊື່ອຖືໄດ້ເທົ່າກັບການເຊື່ອມຕໍ່ທີ່ຢູ່ເບື້ອງຫຼັງເທົ່ານັ້ນ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ຄຸນຄ່າທາງຄລີນິກທັງໝົດຂອງໂຄງການຕິດຕາມຄົນເຈັບທາງໄກຂຶ້ນກັບການເກັບຂໍ້ມູນຢ່າງຕໍ່ເນື່ອງ ຫຼື ເກືອບຕໍ່ເນື່ອງ; ອຸປະກອນທີ່ມີເວລາເຮັດວຽກຕ່ຳສ້າງຊ່ອງຫວ່າງທີ່ງຽບໃນພາບທາງຄລີນິກຂອງຄົນເຈັບ ເຊິ່ງອາດຖືກເຂົ້າໃຈຜິດວ່າເປັນຄວາມຄົງທີ່ (ບໍ່ມີການແຈ້ງເຕືອນເພາະບໍ່ມີຂໍ້ມູນ ບໍ່ແມ່ນເພາະບໍ່ມີຫຍັງປ່ຽນແປງ) ແທນທີ່ຈະຖືກລະບຸຢ່າງຖືກຕ້ອງວ່າເປັນຄວາມລົ້ມເຫຼວຂອງການຕິດຕາມ. ເວລາເຮັດວຽກຂອງອຸປະກອນຍັງເປັນຕົວຊີ້ບອກນຳໜ້າຂອງຕົ້ນທຶນໂຄງການ ແລະ ປະສົບການຂອງຄົນເຈັບ: ອຸປະກອນທີ່ຫຼຸດການເຊື່ອມຕໍ່ເລື້ອຍໆສ້າງການໂທຂໍຄວາມຊ່ວຍເຫຼືອ, ຄວາມອຸກອັ່ງຂອງຄົນເຈັບ ແລະ ການຕິດຕໍ່ທາງຄລີນິກທີ່ອາດບໍ່ຈຳເປັນເພື່ອກວດວ່າຊ່ອງຫວ່າງຂອງຂໍ້ມູນສະທ້ອນເຫດການທາງຄລີນິກແທ້ ຫຼື ພຽງແຕ່ຂໍ້ຜິດພາດທາງເຕັກນິກ. ເນື່ອງຈາກຄວາມລົ້ມເຫຼວດ້ານເວລາເຮັດວຽກຂອງອຸປະກອນມັກເກີດຈາກໂຄງສ້າງພື້ນຖານທີ່ອົງການຄວບຄຸມໄດ້ (ເກດເວຍມືຖືທີ່ຕັ້ງຄ່າບໍ່ດີ, ສັນຍານ Wi-Fi ອ່ອນໃນບ້ານຄົນເຈັບ, ກຸ່ມອຸປະກອນທີ່ບຳລຸງຮັກສາບໍ່ພໍ) ແທນທີ່ຈະເປັນຍ້ອນຄົນເຈັບ ຕົວຊີ້ວັດນີ້ຈຶ່ງຢູ່ກັບຜູ້ໃຫ້ບໍລິການ ແລະ ທີມປະຕິບັດການດ້ານເຕັກນິກຢ່າງຊັດເຈນ ບໍ່ແມ່ນຖືກລວມເຂົ້າກັບຕົວຊີ້ວັດການມີສ່ວນຮ່ວມຂອງຄົນເຈັບໂດຍບໍ່ແຍກແຍະ.

## ວິທີຄຳນວນ

```
ອັດຕາເວລາເຮັດວຽກຂອງອຸປະກອນ = ເວລາທີ່ອຸປະກອນອອນລາຍ ແລະ ສົ່ງຂໍ້ມູນທີ່ຖືກຕ້ອງ /
                              ເວລາຕິດຕາມທີ່ກຳນົດໄວ້ທັງໝົດ × 100

ແບ່ງສາເຫດຫຼັກຂອງເວລາທີ່ບໍ່ເຮັດວຽກ ເມື່ອຂໍ້ມູນອະນຸຍາດ:
  ຄວາມລົ້ມເຫຼວຝັ່ງອຸປະກອນ      (ແບັດເຕີຣີ, ຮາດແວຜິດປົກກະຕິ, ເຟີມແວຄ້າງ)
  ຄວາມລົ້ມເຫຼວດ້ານການເຊື່ອມຕໍ່  (ເຄືອຂ່າຍມືຖື/Wi-Fi/VPN ຫຼຸດ)
  ປັດໄຈຝັ່ງຄົນເຈັບ              (ປິດເຄື່ອງ, ຍ້າຍອອກນອກໄລຍະສັນຍານ)

ພາລາມິເຕີດ້ານເຕັກນິກທີ່ສະໜັບສະໜູນທີ່ຄວນຕິດຕາມຄຽງຄູ່ກັບເວລາເຮັດວຽກ:
  ການໃຊ້ CPU ສະເລ່ຍ, ການໃຊ້ໜ່ວຍຄວາມຈຳ ແລະ ລະດັບແບັດເຕີຣີຕໍ່ອຸປະກອນ
  ເວລາສະເລ່ຍລະຫວ່າງຄວາມລົ້ມເຫຼວຂອງການເຊື່ອມຕໍ່
  ເວລາສະເລ່ຍໃນການເຊື່ອມຕໍ່ໃໝ່ຫຼັງຫຼຸດ
```

## ຕົວຢ່າງການຄຳນວນ

ໂຄງການຕິດຕາມຫົວໃຈທາງໄກນຳໃຊ້ອຸປະກອນເຊື່ອມຕໍ່ 1,000 ເຄື່ອງ ແຕ່ລະເຄື່ອງຄາດວ່າຈະສົ່ງຂໍ້ມູນຢ່າງຕໍ່ເນື່ອງ. ໃນເດືອນ 30 ວັນ (720 ຊົ່ວໂມງຕິດຕາມທີ່ກຳນົດຕໍ່ອຸປະກອນ) ກຸ່ມອຸປະກອນບັນທຶກຊົ່ວໂມງອອນລາຍຕົວຈິງລວມ 705,600 ຊົ່ວໂມງ ເມື່ອທຽບກັບ 720,000 ຊົ່ວໂມງທີ່ກຳນົດ ໃຫ້ອັດຕາເວລາເຮັດວຽກຂອງອຸປະກອນທົ່ວກຸ່ມ 705,600 / 720,000 × 100 = 98%. ການວິເຄາະສາເຫດຫຼັກຂອງ 14,400 ຊົ່ວໂມງທີ່ບໍ່ເຮັດວຽກ ສະແດງວ່າ 60% ມາຈາກການຫຼຸດການເຊື່ອມຕໍ່ເຄືອຂ່າຍມືຖືທີ່ກະຈຸກຢູ່ໃນເຂດບໍລິການຊົນນະບົດສະເພາະ, 25% ມາຈາກອຸປະກອນທີ່ແບັດເຕີຣີເສື່ອມທີ່ຖືກໝາຍໃຫ້ປ່ຽນ, ແລະ 15% ມາຈາກຄົນເຈັບທີ່ປິດອຸປະກອນຊົ່ວຄາວ. ການແບ່ງນີ້ຊີ້ໄປຫາມາດຕະການທີ່ແຕກຕ່າງກັນຢ່າງຊັດເຈນສອງຢ່າງ — ການແກ້ໄຂການເຊື່ອມຕໍ່ສຳລັບເຂດທີ່ໄດ້ຮັບຜົນກະທົບ ແລະ ໂຄງການປ່ຽນແບັດເຕີຣີລ່ວງໜ້າ — ທີ່ຕົວເລກເວລາເຮັດວຽກລວມດຽວຈະບໍ່ໄດ້ແຍກແຍະ.

## ແຫຼ່ງຂໍ້ມູນ ແລະ ຂໍ້ຄວນລະວັງ

ຂໍ້ມູນເວລາເຮັດວຽກມາຈາກລະບົບຈັດການອຸປະກອນ ແລະ ການວັດທາງໄກ (telemetry) ຂອງຜູ້ຜະລິດອຸປະກອນ ຫຼື ຜູ້ໃຫ້ບໍລິການແພລດຟອມເອງ ເຊິ່ງບັນທຶກເຫດການການເຊື່ອມຕໍ່ ແລະ heartbeat ຕໍ່ອຸປະກອນ; ອົງການຄວນຢືນຢັນວ່າຜູ້ໃຫ້ບໍລິການນັບອັນໃດເປັນ "ອອນລາຍ" ຢ່າງແນ່ນອນ (ອຸປະກອນສາມາດລາຍງານຕົນເອງວ່າເຊື່ອມຕໍ່ເຄືອຂ່າຍ ໃນຂະນະທີ່ລົ້ມເຫຼວໃນການສົ່ງຂໍ້ມູນທາງຄລີນິກທີ່ຖືກຕ້ອງ ເຊິ່ງຄວນນັບເປັນເວລາທີ່ບໍ່ເຮັດວຽກສຳລັບຈຸດປະສົງທາງຄລີນິກ ເຖິງແມ່ນແດຊບອດຂອງຜູ້ໃຫ້ບໍລິການລາຍງານວ່າເຊື່ອມຕໍ່ຢູ່). ເວລາເຮັດວຽກຄວນລາຍງານຕາມກຸ່ມອຸປະກອນ ຫຼື ພູມິພາກ ເມື່ອປະລິມານອະນຸຍາດ ເພາະຄຸນນະພາບການເຊື່ອມຕໍ່ມັກກະຈຸກຕາມພູມິພາກ (ສັນຍານມືຖືຊົນນະບົດ, Wi-Fi ຂອງອາຄານເກົ່າ) ແທນທີ່ຈະກະຈາຍເທົ່າກັນທົ່ວປະຊາກອນຄົນເຈັບ ແລະ ຕົວເລກລວມທົ່ວກຸ່ມສາມາດປິດບັງບັນຫາພູມິພາກທີ່ຮ້າຍແຮງ ແຕ່ແກ້ໄຂໄດ້.

## ຈຸດອ່ອນທີ່ຄວນລະວັງ

- **ການປົນການເຊື່ອມຕໍ່ເຄືອຂ່າຍກັບການສົ່ງຂໍ້ມູນທີ່ຖືກຕ້ອງ**: ອຸປະກອນສາມາດປາກົດວ່າ "ເຊື່ອມຕໍ່" ໃນແດຊບອດຂອງຜູ້ໃຫ້ບໍລິການ ໃນຂະນະທີ່ລົ້ມເຫຼວໃນການສົ່ງຂໍ້ມູນທາງຄລີນິກທີ່ໃຊ້ໄດ້; ຄວນກຳນົດ ແລະ ວັດເວລາເຮັດວຽກຕາມການໄດ້ຮັບຂໍ້ມູນທີ່ຖືກຕ້ອງຈິງ ບໍ່ແມ່ນພຽງການເຊື່ອມຕໍ່ເຄືອຂ່າຍດິບ.
- **ການລາຍງານສະເພາະຄ່າສະເລ່ຍທົ່ວກຸ່ມ**: ສິ່ງນີ້ສາມາດປິດບັງບັນຫາເວລາບໍ່ເຮັດວຽກທີ່ຮ້າຍແຮງສະເພາະພູມິພາກ ຫຼື ກຸ່ມອຸປະກອນ ທີ່ຄ່າສະເລ່ຍທີ່ເຈາະຈົງຈະເປີດເຜີຍ ແລະ ມີວິທີແກ້ໄຂສະເພາະທີ່ເຮັດໄດ້.
- **ການບໍ່ແຍກສາເຫດຫຼັກຂອງເວລາບໍ່ເຮັດວຽກ**: ເວລາບໍ່ເຮັດວຽກຝັ່ງອຸປະກອນ, ການເຊື່ອມຕໍ່ ແລະ ຝັ່ງຄົນເຈັບ ແຕ່ລະຢ່າງຕ້ອງການມາດຕະການທີ່ແຕກຕ່າງກັນຢ່າງສິ້ນເຊີງ; ເປີເຊັນເວລາບໍ່ເຮັດວຽກດຽວທີ່ບໍ່ມີການແບ່ງຕາມສາເຫດຫຼັກບໍ່ສາມາດນຳໄປດຳເນີນການໄດ້.
- **ການຖືວ່າຊ່ອງຫວ່າງຂອງຂໍ້ມູນເປັນຄວາມຄົງທີ່ທາງຄລີນິກໂດຍຄ່າເລີ່ມຕົ້ນ**: ກະແສຂໍ້ມູນທີ່ຂາດຫາຍຈາກອຸປະກອນທີ່ອອບລາຍຄວນກະຕຸ້ນການກວດສອບການເຊື່ອມຕໍ່ທາງເຕັກນິກ ບໍ່ແມ່ນຖືກຕີຄວາມໝາຍຢ່າງງຽບໆວ່າ "ບໍ່ມີຂ່າວແມ່ນຂ່າວດີ" ສຳລັບສະຖານະທາງຄລີນິກຂອງຄົນເຈັບ.

## ແຫຼ່ງອ້າງອີງ

- Continua Design Guidelines / Personal Connected Health Alliance, technical interoperability standards for connected health devices
- ONC / HealthIT.gov, guidance on remote patient monitoring programme implementation and technical requirements
- Peer-reviewed literature on remote patient monitoring device reliability and data completeness, for example studies published in npj Digital Medicine
