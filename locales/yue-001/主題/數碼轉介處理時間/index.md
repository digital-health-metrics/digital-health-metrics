# 數碼轉介處理時間

數碼轉介處理時間係指由轉介臨床人員提交電子轉介，到接收服務完成分流並接受、拒絕或者安排預約所經過嘅時間。佢係一個流程（流量）指標，有別於病人嘅總輪候時間，亦係最清晰地顯示數碼系統改變（結構化電子轉介、基於影像嘅分流、標準化轉介表格）可以推動一個營運數字，而唔只係滿意度分數嘅地方之一。

## 點解重要

緩慢或者變化極大嘅分流步驟，會喺病人加入臨床輪候名單之前就已經增加延誤，而由於呢個延誤發生喺任何臨床護理開始之前，所以係純粹嘅流程浪費，數碼工具好適合消除。強制「退回轉介者」補充缺漏資料嘅轉介系統，會造成返工循環，如果處理時間只係量度第一次就順利通過嘅轉介，就好容易忽略呢啲循環。喺服務引入結構化數碼轉介表格、必填欄位或者基於影像嘅分流（例如遠程皮膚科）之處，處理時間通常係展示效益最有說服力嘅單一指標，因為可以用同一套工具量度改變前後嘅數字。

## 點計算

```
處理時間 = 時間戳記（分流決定）− 時間戳記（提交轉介）

匯報中位數同較高百分位數（通常係第 90 百分位），
而唔係只匯報平均值，
因為分佈會被退回或者複雜嘅轉介嚴重拉向右邊。

如果系統有記錄，可考慮分階段時間：
  提交 → 服務接收
  接收 → 分流決定
  分流決定 → 已安排預約（如適用）
```

## 計算示例

一個電子轉介系統嘅審計追蹤顯示，所有專科由提交到分流決定嘅中位數時間為 1.8 日，第 90 百分位時間為 6 日，主要由於轉介因缺少臨床資料而被退回轉介者。同一平台上，一條採用基於影像分流嘅遠程皮膚科路徑，達到 4 小時嘅中位數處理時間同 1 日嘅第 90 百分位，因為一張相片同結構化病史，幾乎都足以作出分流決定，而無需進一步通訊。

## 數據來源同注意事項

電子轉介或者轉介管理系統本身嘅審計追蹤係主要來源，使用提交同決定嘅時間戳記；機構應該確認，當轉介被退回補充資料時，「時鐘」係暫停定係持續運行，因為兩種定義對同一個底層流程會產生實質上唔同嘅數字。處理時間應該一致地以日曆時間或者辦公時間匯報，否則週末同假期嘅影響可能扭曲工作模式唔同嘅服務之間嘅比較。

## 常見陷阱

- **只量度「乾淨」嘅轉介**：喺計算中剔除被拒絕或者退回嘅轉介，會隱藏數碼工具通常專門用嚟減少嘅返工負擔。
- **匯報平均值而唔係中位數同百分位數**：少數長期處理中、被退回嘅轉介，會將平均值拉到遠高於典型病人實際經歷嘅水平。
- **將處理時間同總輪候時間混為一談**：處理時間只涵蓋分流步驟；病人嘅總體驗亦包括下游嘅臨床輪候名單，而呢個係受獨立容量限制影響嘅另一個指標。
- **冇區分子階段**：只量度端對端時間嘅服務，無法判斷數字偏慢係因為轉介者提交資料不完整、接收服務嘅分流容量，定係兩者皆有。

## 資料來源

- NHS England，e-Referral Service (e-RS) 統計同服務規格
- 有關電子轉介管理系統同數碼分流路徑（包括遠程皮膚科）嘅同行評審文獻
- ONC / HealthIT.gov，互操作性同轉介協調指引
