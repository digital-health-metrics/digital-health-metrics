# 急症室分流率

急症室（ED）分流率量度由數碼分流或者虛擬護理工具處理嘅病人接觸之中，如無該干預本來大概會導致急症室就診、但反而透過較低緊急程度路徑——自我護理建議、基層醫療預約或者已安排嘅緊急護理診症——安全處理嘅比例。佢係分流轉送準確度（見該主題）一個具體而高價值嘅子集，完全聚焦於避免嘅急症室使用量，而呢個係同醫療成本同急症室容量紓緩最直接掛鈎嘅結果。

## 點解重要

急症室係每次就診成本最高昂嘅護理環境之一，經常用嚟處理本來可以喺其他地方安全管理嘅問題，所以數碼分流工具安全咁將適當個案轉離急症室嘅能力，係其商業同營運上最有價值嘅能力之一——亦係最容易向評估工具投資回報嘅付款方或醫療系統解釋嘅能力之一。不過，分流只有喺安全嘅情況下先有價值：一個積極將病人分流離開急症室、但代價係錯過真正緊急情況嘅工具，完全優化咗取捨嘅錯誤一邊，所以急症室分流率必須永遠連同追蹤被分流病人入面錯過或延誤急症就診嘅安全指標一齊匯報，而唔係孤立咁當成純粹嘅效率勝利去匯報。

## 點計算

```
急症室分流率 = 安全咁被轉向離開急症室、前往適當較低緊急
               程度路徑嘅病人接觸 / 被評估為可能前往急症室
               嘅病人接觸總數 × 100

「安全咁轉向」需要透過跟進或者相連嘅健康紀錄數據確認，
病人嘅病況喺界定嘅跟進時間窗內（例如 72 小時）
並無實際需要急症護理——分流決定並唔會僅僅
因為病人其後冇即時去急症室就被驗證為安全。

連同以下指標一齊匯報：
  錯過急症率 = 喺跟進時間窗內確實需要急症護理嘅被分流病人 /
               被分流病人總數 × 100
```

## 計算示例

一項數碼分流服務喺一個月內評估 3,000 個被其臨床演算法判斷為如無干預可能前往急症室嘅病人接觸。其中 1,800 個被轉向較低緊急程度路徑（分流率 60%）。使用相連嘅健康紀錄數據，喺 72 小時對被分流同期群進行跟進，發現 1,800 名被分流病人之中，有 45 人其後喺該時間窗內確實到過急症室（錯過急症率為 45 / 1,800 × 100 = 2.5%）。如果匯報 60% 嘅分流數字而冇 2.5% 嘅錯過急症率，就只係展示咗決定工具分流行為係咪校準適當嘅安全與效率取捨嘅其中一半。

## 數據來源同注意事項

確認被分流嘅病人其後並無需要急症護理，取決於相連嘅數據——同一醫療系統自己嘅急症室紀錄、區域健康資訊交換，或者結構化嘅病人跟進電話或問卷——而喺冇任何呢啲數據來源之下運作嘅分流計劃，實際上無法驗證自己嘅安全性，只能基於冇投訴而作出假設。適當嘅分流率同可接受嘅錯過急症率係臨床政策決定，而非純粹統計決定，應該由臨床領導層刻意制定，而唔係任由其成為分流演算法碰巧默認使用嘅任何門檻嘅副產品。分流率應該按就診症狀或主訴類別匯報，因為適當嘅分流率因病況而差異極大（輕微割傷同胸痛需要極為唔同嘅分流門檻）。

## 常見陷阱

- **匯報分流率而冇相連嘅錯過急症安全指標**：透過分流不足真正緊急個案而達到嘅高分流率並非成功；兩個指標必須永遠一齊匯報。
- **假設冇急症室就診就表示分流係安全**：病人可能到另一間、並未相連嘅醫院系統嘅急症室，或者可能出現真正有害嘅結果而從未到任何急症室；應該透過相連數據或者結構化跟進去驗證安全，而唔係單靠同一系統內冇急症室就診。
- **純粹為咗盡量提高分流率而設定分流門檻**：喺冇相應安全限制之下調校成盡量提高分流嘅演算法或政策，會用病人安全去換取更好睇嘅效率數字。
- **將分流率跨所有主訴類型混合**：適當嘅分流率因就診主訴而差異極大；單一混合比率無法顯示工具對臨床上最重要嘅特定病況係咪安全有效咁運作。
