# 介入時間

介入時間係指由自動健康警示產生——例如遠程監測裝置偵測到超出範圍嘅生命徵象，或者數碼分流工具標記出病情惡化嘅病人——到臨床團隊成員實際開始回應所經過嘅時間。佢係決定自動警示系統能否兌現其核心承諾嘅流程指標：比起傳統嘅定期覆診或者病人主動致電模式，更早捕捉到問題。

## 點解重要

一個產生臨床上正確警示、但冇得到及時回應嘅警示系統，實際上並冇改善病人安全；遠程監測同自動警示嘅整個價值主張，建基於比無監測嘅替代路徑更快閉環。由於唔同嚴重程度嘅警示需要唔同嘅回應緊急程度，所以介入時間應該永遠按嚴重程度層級匯報，而唔係單一平均值，因為所有警示嘅快速平均值，可以隱藏對少數最嚴重警示嘅危險地緩慢回應。呢個指標亦係向臨床領導層同付款方展示自動監測計劃價值最清晰、最有說服力嘅方法之一，因為可以直接同同一機構之前針對類似臨床情況嘅非自動化回應時間作比較。

## 點計算

```
介入時間 = 時間戳記（臨床回應開始）−
           時間戳記（警示產生）

匯報中位數同較高百分位數（例如第 90 百分位），
按警示嚴重程度層級分層，而唔係單一混合平均值。

「臨床回應開始」應該被精確而一致咁界定——
例如臨床人員打開病人紀錄並採取行動，或者有記錄嘅
主動聯絡嘗試——而唔係單純睇過或者確認警示而冇採取任何行動。
```

## 計算示例

一個遠程心臟監測計劃嘅警示系統，喺一個月內標記 200 個高嚴重程度心律不正警示。由警示產生到臨床人員開始主動聯絡嘅中位數時間為 12 分鐘，第 90 百分位時間為 38 分鐘。同一人群之前非監測路徑（類似事件通常要等到下一次定期門診覆診或者入院先會浮現）嘅歷史數據顯示，任何臨床回應嘅中位數時間以日計，而唔係以分鐘計。呢個比較——而唔係孤立嘅 12 分鐘數字——先係展示監測計劃臨床價值嘅所在；第 90 百分位嘅數字同樣重要，因為佢識別出需要超過半個鐘頭先採取行動嘅尾部警示，值得進行獨立嘅根本原因檢討。

## 數據來源同注意事項

警示產生嘅時間戳記來自監測平台本身嘅事件日誌；臨床回應嘅時間戳記通常來自電子健康紀錄嘅審計追蹤，或者護理團隊本身嘅工作流程或任務管理系統，而呢兩個系統必須精確咁時間同步，計算出嚟嘅時段先值得信賴。「回應開始」需要嚴格、有文件記錄嘅定義，因為臨床人員單純睇過或者忽略警示而冇進一步行動，同觸發實際主動聯絡或者介入係根本上唔同、亦遠遠不及令人安心嘅事件——將兩者混為一談，會令回應時間睇落比臨床現實更好。通宵同週末嘅人手水平通常會顯著影響介入時間，所以喺警示數量許可嘅情況下，呢個指標應該按一日內時段同星期幾分段匯報，而唔係只係全日候混合平均值，因為後者可以掩蓋嚴重嘅非辦公時間回應差距。

## 常見陷阱

- **將確認警示當成回應**：臨床人員睇過或者忽略警示，同開始臨床回應並不相同；應該將回應嚴格界定為有記錄嘅行動，而唔係被動確認。
- **匯報跨所有嚴重程度嘅單一混合時間**：低同高嚴重程度警示合併嘅快速平均值，可以隱藏專門針對最重要嘅最高嚴重程度警示嘅危險地緩慢回應時間。
- **忽略人手模式嘅影響**：回應時間往往因人手水平而隨一日內時間同星期幾有顯著差異；單一整體平均值可以隱藏系統性嘅非辦公時間或者週末回應差距。
- **比較警示門檻唔同嘅機構嘅介入時間**：採用較保守（較敏感）警示門檻嘅機構會產生更多低緊急程度警示，同採用較嚴格門檻嘅機構相比，會攤薄其平均回應時間，同實際臨床回應能力無關。
