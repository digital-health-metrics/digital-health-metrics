# 裝置運作時間比率

裝置運作時間比率量度連接健康裝置——遠程病人監測感應器、穿戴裝置或者家居遠程醫療設備——喺預定監測時間內，實際在線、傳送數據同正常運作（而非離線、斷線或者故障）嘅時間比例。佢係每個遠程監測或連接裝置計劃底層嘅基礎設施指標：一個臨床警示、一個生物指標趨勢，或者一個由經常離線嘅裝置計算出嚟嘅參與度數字，可靠程度只會同其背後嘅連線一樣。

## 點解重要

遠程病人監測計劃嘅整個臨床價值主張，取決於持續或者接近持續嘅數據捕捉；運作時間欠佳嘅裝置，會喺病人嘅臨床圖像中造成無聲嘅空隙，可能被誤認為穩定（冇警示係因為冇數據，而唔係因為冇變化），而唔係被正確識別為監測失敗。裝置運作時間亦係計劃成本同病人體驗嘅領先指標：經常斷線嘅裝置會引致支援電話、病人沮喪，以及可能不必要嘅臨床跟進，去查核數據空隙係反映真實臨床事件，定係單純技術故障。由於裝置運作時間故障，往往可以歸因於機構控制範圍內嘅基礎設施（配置欠佳嘅流動網絡閘道器、病人家中薄弱嘅 Wi-Fi 覆蓋、維護不足嘅裝置群），而唔係病人，所以呢個指標應該屬於供應商同技術營運團隊，而唔係不加區分咁併入病人參與度指標。

## 點計算

```
裝置運作時間比率 = 裝置在線並傳送有效數據嘅時間 /
                   預定監測總時間 × 100

喺數據許可嘅情況下，按成因分層停機時間：
  裝置端故障   （電池、硬件故障、韌體崩潰）
  連線故障     （流動網絡／Wi-Fi／VPN 中斷）
  病人端因素   （裝置關機、移出範圍）

連同運作時間一齊追蹤嘅支援技術參數：
  每部裝置嘅平均 CPU 使用率、記憶體使用量同電池電量
  連線故障之間嘅平均時間
  中斷後重新連線嘅平均時間
```

## 計算示例

一個遠程心臟監測計劃部署 1,000 部連接裝置，每部預期持續傳送數據。喺 30 日嘅一個月（每部裝置 720 個預定監測小時）內，成批裝置合共記錄 705,600 個實際在線小時，對比預定嘅 720,000 小時，得出全批裝置運作時間比率為 705,600 / 720,000 × 100 = 98%。對 14,400 個停機小時進行根本原因分析顯示，60% 歸因於集中喺某個鄉郊服務地區嘅流動網絡連線中斷，25% 歸因於被標記需要更換、電池老化嘅裝置，15% 歸因於病人暫時關閉裝置。呢個分拆指向兩個清晰而唔同嘅干預措施——針對受影響地區嘅連線修復，同主動式電池更換計劃——而單一總體運作時間數字就無法區分到呢兩者。

## 數據來源同注意事項

運作時間數據來自裝置製造商或者平台供應商本身嘅裝置管理同遙測系統，該系統會按裝置記錄連線同心跳事件；機構應該確認供應商究竟將乜嘢計為「在線」（裝置可以匯報自己已連接網絡，但無法傳送有效臨床數據，就臨床目的而言，即使供應商自己嘅儀表板匯報為已連線，都應該計為停機）。喺數量許可嘅情況下，運作時間應該按裝置同期群或者地理位置匯報，因為連線質素往往集中於地理區域（鄉郊流動網絡覆蓋、舊樓宇 Wi-Fi），而唔係平均分佈喺病人人群之中，而全批裝置嘅總體數字可以掩蓋嚴重、可以處理嘅地區性問題。

## 常見陷阱

- **將網絡連線同有效數據傳送混為一談**：裝置可以喺供應商儀表板上顯示為「已連線」，但無法傳送可用嘅臨床數據；應該對照實際收到有效數據去界定同量度運作時間，而唔係單靠原始網絡連線。
- **只匯報全批裝置平均值**：咁樣可以隱藏嚴重、特定於地理位置或者裝置同期群嘅停機問題，而針對性嘅平均值會揭示出嚟，並且有具體、可以處理嘅解決方法。
- **冇區分停機成因**：裝置端、連線同病人端停機，各自需要完全唔同嘅干預；單一停機百分比而冇按成因分層，無法付諸行動。
- **默認將數據空隙視為臨床穩定**：離線裝置缺失嘅數據流，應該觸發技術連線檢查，而唔係被靜靜地解讀為病人臨床狀況「冇消息就係好消息」。
