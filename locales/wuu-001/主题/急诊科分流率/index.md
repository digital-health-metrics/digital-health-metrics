# 急诊科分流率

急诊科（ED）分流率是指由数字分诊工具或虚拟护理处理个患者接触中，若无该干预、蛮可能会导致急诊就诊，但实际上通过较低急重程度路径——自我护理建议、初级护理预约，或预约个紧急护理就诊——得到安全管理个比例。这是分诊转介准确率（参见该主题）中一个特定个、高价值个子集，专注于避免个急诊科利用，而这正是与医疗成本和急诊容量缓解最直接相关个结果。

## 为何重要

急诊科是每次接触成本最高个护理场所之一，常被用于本可在其他地方安全处理个问题，因此数字分诊工具将适当病例安全地引导离开急诊科个能力，是其最具商业和运营价值个能力之一——也是向评估该工具投资回报个支付方或医疗系统传达价值最容易个方式之一。但分流只有在安全个前提下才有价值：一款以漏诊真正急症为代价而激进分流个工具，完全权衡错了方向，这正是为何急诊科分流率必须始终与一项追踪被分流患者中漏诊或延误急症个安全性指标一并报告，而勿应孤立地作为纯粹个效率胜利单独报告。

## 计算方法

```
急诊科分流率 = 安全转介至适当低急重程度路径的患者接触数 /
               评估为可能急诊倾向的患者接触总数 × 100

"安全转介"需要通过随访或关联健康档案数据来确认，患者的
病情在特定随访窗口内（例如72小时）实际上并未需要急诊护
理——不能仅因患者事后未立即前往急诊科，就认定该分流决
定已被验证为安全。

应一并报告：
  漏诊急症率 = 在随访窗口内确实需要急诊护理的被分流患者数 /
              被分流患者总数 × 100
```

## 实例解析

某数字分诊服务在一个月内评估了3000次其临床算法判断为可能急诊倾向个患者接触。其中1800次被转介至较低急重程度路径（分流率60%）。使用关联健康档案数据对被分流队列进行72小时随访发现，1800名被分流患者中有45人在该窗口内确实前往急诊科就诊（漏诊急症率为45 / 1800 × 100 = 2.5%）。若仅报告60%个分流数字而不报告2.5%个漏诊急症率，则只呈现了实际决定该工具分流行为是否适当校准个安全性-效率权衡个一半。

## 数据来源与注意事项

确认被分流患者随后并未需要急诊护理，依赖于关联数据——同一医疗系统自身个急诊科记录、区域健康信息交换，或结构化个患者随访电话或调查——如果分流项目在运行时呒没迪眼数据支持，实际上无法验证自身个安全性，只能基于呒没投诉这一现象来假设安全。适当个分流率和可接受个漏诊急症率，是临床政策决策，而非纯粹个统计决策，应由临床领导层有意识地设定，而勿应任其成为分诊算法默认使用个某个阈值个附带结果。应按就诊症状或主诉类别报告分流率，因为适当个分流率因病情而异极大（例如小裂伤与胸痛需要截然不同个分流阈值）。

## 常见误区

- **报告分流率却呒没关联个漏诊急症安全性指标**：通过低估真正急症个分诊而实现个高分流率并非成功；必须始终将这两项指标一并报告。
- **假设呒没急诊就诊就意味着分流是安全个**：患者可能前往另一个未关联个医院系统个急诊科，或在从未就诊任何急诊科个情况下出现真正有害个结果；应通过关联数据或结构化随访来验证安全性，而非仅凭同一系统内呒没急诊就诊记录。
- **纯粹为最大化分流率而设定分流阈值**：一个为最大化分流而调优、却呒没匹配安全约束个算法或政策，会以患者安全换取看似更好个效率数字。
- **跨所有主诉类型合并分流率**：适当个分流率因就诊主诉而异极大；单一个综合比率无法说明该工具在临床上最重要个特定病情上是否表现安全有效。
