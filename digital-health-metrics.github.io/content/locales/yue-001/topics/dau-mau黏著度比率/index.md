# DAU/MAU 黏著度比率

DAU/MAU 黏著度比率將每日活躍用戶（DAU）同每月活躍用戶（MAU）作比較——用於每週活躍用戶（WAU）對 MAU 嘅基礎量度亦相同——用嚟表達產品較廣泛嘅用戶群之中，喺任何一日有幾多比例會同產品互動。佢係量度參與強度嘅標準產品分析指標，有別於用戶是否被留住（見用戶留存率），亦有別於某一位特定登記病人隨時間參與得幾有規律（見病人參與持續率）：黏著度描述嘅係人群層面嘅使用節奏，而唔係任何個人嘅模式。

## 點解重要

兩個數碼健康產品可以匯報完全一樣嘅每月活躍用戶數，但背後嘅參與強度可以好唔同：一個係大部分用戶幾乎每日都開啟應用程式，另一個係大部分用戶喺快將被視為不活躍之前先每月開啟一次。DAU/MAU 黏著度比率用一個簡單、容易理解嘅基準數字，就可以分辨呢兩種截然不同嘅情況，產品同臨床團隊可以隨時間追蹤，並且同已知嘅行業範圍作比較——約 20% 嘅比率係好多消費者應用程式常被引用嘅合理基準，而每日習慣型產品（預期病人每日使用嘅飲食或症狀日記）應該用高明顯嘅標準去衡量。由於黏著度對「活躍」嘅定義好敏感，所以最有用嘅係用嚟睇同一個產品隨時間嘅趨勢，以及同為類似使用模式而設計嘅產品作比較，而唔係當成跨行業嘅絕對基準。

## 點計算

```
DAU/MAU 黏著度比率 = 該時期平均每日活躍用戶 /
                     同一時期嘅每月活躍用戶 × 100

WAU/MAU 比率（按週，原理相同）係較寬鬆嘅變體，
更適合預期每星期使用幾次而非每日使用嘅產品。

「活躍」必須喺分子同分母之中都被精確而一致咁界定
（例如一項完成嘅合資格操作，而唔係被動開啟應用程式）。
```

## 計算示例

一個數碼糖尿病管理應用程式喺某個月有 10,000 名每月活躍用戶，定義為喺該月內完成至少一項合資格操作（血糖記錄、飲食記錄或者服藥打勾）嘅任何用戶。將該月 30 日嘅每日活躍用戶數目取平均，得出平均 DAU 為 2,200。DAU/MAU 黏著度比率為 2,200 / 10,000 × 100 = 22%，顯示喺一個典型嘅日子，應用程式每月用戶群之中約有 22% 會同佢互動——對於每日習慣型嘅慢性病工具而言係合理嘅數字，不過產品團隊會希望見到佢隨時間向上趨升，因為理想行為（每日記錄）對登記病人嚟講會變得越嚟越習慣。

## 數據來源同注意事項

DAU、WAU 同 MAU 全部都係由同一組事件日誌計算，並且喺每個時間窗都使用一致嘅「合資格活躍」事件定義；喺分子同分母計算之間更改呢個定義（例如 DAU 計算任何應用程式開啟，但 MAU 只計算完成嘅操作），會產生扭曲嘅比率，無法反映真實嘅參與強度。黏著度嘅適當基準好大程度取決於產品預期嘅使用模式：一個預期每星期使用一次嘅工具（每週症狀登記）會、亦應該有比預期每日使用嘅工具（連續血糖監測伴侶應用程式）低嘅 DAU/MAU 比率，所以解讀黏著度時，應該永遠對照產品本身預期嘅使用頻率，而唔係單一嘅通用目標。

## 常見陷阱

- **比較預期使用頻率唔同嘅產品嘅黏著度比率**：即使兩者都完全按其各自使用場景嘅預期運作，每週使用嘅工具喺結構上都會顯示比每日使用嘅工具低嘅 DAU/MAU 比率；應該對照產品本身預期嘅頻率作基準，而唔係單一通用目標。
- **喺分子同分母使用不一致嘅活動定義**：咁樣會產生一個無法反映真實參與強度嘅黏著度比率，亦無法有意義咁隨時間或者同其他產品比較。
- **未睇整體 MAU 趨勢就將黏著度上升視為絕對正面**：如果比率上升係由於整體 MAU 下降而核心用戶群縮小但更習慣使用所致，同一個穩定或者增長嘅用戶群之中每日參與真正增加所帶動嘅上升，係非常唔同——亦更令人擔憂——嘅情況。
- **忽略 DAU 嘅星期幾同季節性影響**：對於好多健康產品，DAU 可以因星期幾（平日對比週末）或者季節而有顯著變化；應該採用涵蓋完整自然週期嘅時期嘅平均 DAU，而唔係可能出現偏差嘅短時間窗。
